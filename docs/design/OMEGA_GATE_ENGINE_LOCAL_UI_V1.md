# عقد دمج محرك بوابات Ω مع VX Runtime — V1

**الحالة:** IMPLEMENTED_AS_DESIGN_DOCUMENT / INTEGRATION_NOT_VERIFIED  
**الفرع:** `feat/omega-gate-engine-local-ui-20261031`  
**الحدود:** لا تعديل لـ `project.genome` أو `Ω.000`، لا دمج، لا نشر، لا إنفاق، ولا استدعاء لمزود خارجي.

## 1. القرار المعماري

محرك البوابات Ω المرفق واجهة تشغيل/عرض محلية (operator workbench)، وليس مصدر سلطة أو محرك قبول مستقل. لا يجوز للواجهة أن تنشئ حالة Canonical أو تمنح `ADMITTED` اعتماداً سيادياً. وظيفتها جمع المدخلات، عرض حالات البوابات، وإظهار مراجع الأدلة ونتائج التحقق الصادرة من خدمات VX الموثوقة.

يُمنع بناء سجل أدلة أو محرك توقيع موازٍ. يستمر VX Runtime في امتلاك التنفيذ والسجل، وتبقى سلطة الاعتماد خارج الواجهة.

## 2. حدود المسؤولية

| الطبقة | المسؤولية | ما لا يجوز لها |
|---|---|---|
| Ω Gate UI | عرض الحالة، إدخال المراجع، تشغيل تحقق محلي محدود | توقيع أو اعتماد أو تعديل الحالة canonical |
| VX Runtime | تنفيذ السياسات، تسجيل الأحداث، إعادة التشغيل | اعتبار بيانات الواجهة هوية موثوقة |
| SCCK verifier | التحقق من التوقيع/الحمولة/الإثبات وفق السياسة المهيأة | تثبيت الحزمة أو الادعاء بالاعتماد السيادي |
| VV / independent verifier | إعادة التحقق من الأدلة والنتائج | الاعتماد على تقرير ذاتي من UI |
| V / authority | قرار الترقية النهائي وفق الصلاحيات | تفويض الواجهة لنفسها |

## 4. عقد سجل الأدلة

كل عنصر دليل يعرض في الواجهة يجب أن يحمل على الأقل:

- `evidence_id` ثابتاً.
- `evidence_type` من قائمة مسموحة.
- `subject_id` ونسخة الأصل.
- `source_ref` (commit / workflow run / artifact / verifier report).
- `content_digest` بصيغة SHA-256.
- `observed_at` من مصدر وقت موثوق أو موسوم بوضوح كوقت محلي.
- `verification_status` مستقلاً عن حالة الأصل.
- `verifier_id` ونسخة أداة التحقق عند توفرهما.

هاش SHA-256 يثبت تطابق المحتوى فقط؛ لا يثبت المصدر أو هوية المنشئ أو زمن الإنشاء. لا يُسمى hash chain توقيعاً رقمياً. يجب أن يتحقق الخادم من كل مرجع ومحتوى قبل استخدامه في قرار.

## 5. متطلبات الأمان للواجهة

1. جميع مدخلات المستخدم غير موثوقة؛ يجب ترميزها قبل العرض وعدم إدخالها مباشرة في `innerHTML`.
2. الافتراضي loopback/local-only؛ لا شبكة ولا API تلقائي ولا تحميل حزم أو تشغيل كود من مدخلات المستخدم.
3. أي اتصال لاحق يجب أن يمر عبر adapter VX محدود الصلاحيات، مع CSRF/authentication/rate limits وallowlist للأوامر.
4. لا تُخزن المفاتيح الخاصة أو بيانات الاعتماد في HTML أو المتصفح أو ملف JSON المُصدّر.
5. التصدير يصف سجل المحاكاة المحلي ولا يتحول إلى إيصال قبول أو سجل سيادي.
6. كل فشل تحقق يجب أن يكون fail-closed؛ لا يُسمح بالترقية عند غياب الدليل أو تعذر الوصول إليه.
7. لا يُستنتج MISSING من NOT_OBSERVED أو INACCESSIBLE.

## 6. التكامل مع الموجود — منع التكرار

- يستخدم محرك الواجهة عقود VX الحالية ولا ينشئ Ledger أو AdmissionStore موازياً.
- تنفيذ SCCK المحلي في `vxruntime/scck.py` هو نقطة التحقق الحالية للحزم المحلية؛ لا يُعاد تنفيذ Ed25519 أو Merkle في الواجهة.
- PR #31 يحتوي مساراً منفصلاً لمدقق SCCK cryptographic/no_std؛ يجب مراجعته ودمجه مع مسار SCCK القائم قبل أي تكامل UI معه.
- PR #33 سجل إغلاق تدقيق SCCK، وPR #34 عقد adapter محمّل VX ONE؛ يجب عدم إعادة إنشاء وظائفهما.
- هذا المستند لا يثبت أن أياً من PRs المذكورة مدمج أو VERIFIED.

## 7. خطة التكامل الآمنة

1. **Inventory:** مطابقة حالات البوابات مع واجهات VX الحالية ومخرجات SCCK/CI دون تعديلها.
2. **Read-only adapter:** توفير استعلامات قراءة فقط للـ UI، مع مخرجات schema-versioned.
3. **Evidence binding:** ربط كل دليل بـ commit/workflow/artifact digest؛ لا قبول مراجع حرة كأدلة مثبتة.
4. **Independent verification:** إعادة التحقق على الخادم/CI، لا في المتصفح وحده.
5. **Authority decision:** إنشاء قرار ترقية منفصل خارج UI؛ لا endpoint للقبول الذاتي.
6. **Security review:** XSS/CSRF/authz/replay/rate limits/secret handling.
7. **CI:** اختبارات contract وnegative tests وtamper tests على نفس commit.
8. **Promotion:** يظل HOLD حتى مراجعة مستقلة وموافقة منفصلة.
