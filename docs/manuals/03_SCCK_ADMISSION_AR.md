# بوابة قبول SCCK المحلية داخل VX

الحالة IMPLEMENTED_LOCAL_REFERENCE؛ اعتماد الإنتاج HOLD.
المصدر الأساسي قبل التعديل: `7fc4fcebb7fccdb70e379df7a52fa7826b4bb2c9`.
متطلبات المستخدم محفوظة دون تعديل في `docs/design/scck-source-ar.txt`.
الرموز المفقودة في التقرير لم تُستعد تخمينًا؛ الاختبارات تصرّح بحالة قبول 10
ثم رفض 9. هذا تنفيذ Python متوافق مع النواة الموجودة؛ ليس Rust أو no_std.

## العقد والتنفيذ

المدخلات `Manifest` و`Package` من `vxruntime/scck.py`. المخرج معرف قبول دائم
أو `SCCKError` برمز ثابت. Ed25519 يوقع جميع حقول البيان، بما فيها العملية
والبروتوكول. الترميز ASCII JSON بمفاتيح مرتبة وفواصل دون مسافات، أعداد صحيحة
فقط، وبادئة موقعة `VAIXLNS/SCCK/MANIFEST/REFERENCE-1\0`.
هذا بروتوكول مرجعي محلي؛ لا ادعاء امتثال لمواصفة SCCK خارجية أو JSON RFC.

SHA-256 يقارن الحمولة الفعلية، وMerkle يستخدم أزواجًا مرتبة وبادئتين منفصلتين
للأوراق والعقد. الجذر يأتي من سياسة مستقلة يثبتها المضيف، وليس ثقة بالحزمة.
النطاق `(package_id, device_id, component)`؛ الحقبة تُفحص داخله ولا تعيد ضبط
أعلى إصدار. المفاتيح والحقبة والجذر والمنفذ وصلاحية تفويضه مقيدة بهذا النطاق
وبالعملية الوحيدة `scck.inspect.v1`، دون wildcards.

الفحوص المكلفة خارج معاملة الكتابة. داخل `BEGIN IMMEDIATE` تُقرأ السياسة
الحالية والإلغاء والصلاحية والحقبة والجذر وأعلى إصدار. القبول وتحديث أعلى
إصدار وسجل التدقيق في معاملة واحدة. SQLite يستخدم WAL و`synchronous=FULL`
لكل اتصال. المكتبة لا تفرض مهلة إلغاء للعملية؛ الفحوص محدودة الحجم وانتظار
قفل قاعدة البيانات خمس ثوانٍ ثم يفشل دون قبول.

`AdmissionStore.inspect` يعيد التحقق من الحزمة والسياسة ويستخدم `VXRuntime`
و`ExecutionPolicy` القائمين لتنفيذ عامل ثابت يحسب الحجم والبصمة فقط. يسجل
بصمات المدخل والمخرج وحدث النواة. لا يشغّل بايتات الحزمة أو يثبتها، ولا يغير
`evaluate_admission` أو يجعل القبول اعتمادًا سياديًا.

## الحالة والاستئناف

`ACCEPTED → EXECUTING → SUCCEEDED | FAILED`.

- لا تنفيذ لطلب مقبول دون فحص حالي جديد. قبول إصدار أحدث يمنع بدء الأقدم.
- فشل العامل لا يخفض أعلى إصدار ولا يجيز التراجع التلقائي.
- انقطاع أثناء EXECUTING يظهر في `recovery_holds()`؛ لا إعادة تلقائية، ويلزم
  قرار تعافٍ مستقل. فشل كتابة النتيجة بعد بدء العامل يترك الحالة نفسها.
- التفويض يجيز بدء الفحص المحلي. لا ادعاء تفويض مستمر بعد البدء أو exactly-once
  لآثار خارجية؛ لا آثار تثبيت أو شبكة في العامل.
- لا يحذف المسار سجلات القبول. أحداث الرفض لا تُحفظ حاليًا؛ يعاد رمزها للمضيف.

## حدود الثقة

هذه مكتبة خلفية وليست مصادقة. `provision_scope` للمضيف الموثوق وحده بعد تحقق
هوية المسؤول وصلاحيته. `principal` والساعة يأتيان من المضيف، ولا يثبت النص أو
كائن Python هويتهما. لا تعرض الدوال مباشرة كأدوات عامة أو HTTP. لا يصدر هذا
الكود مفاتيح أو تفويضات إنتاج ولا يربط الحكومة أو المزودين الخارجيين.

قاعدة البيانات خاصة على قرص محلي يدعم القفل والمزامنة. لا مقاومة هنا لمسؤول
يعيد قاعدة البيانات إلى نسخة قديمة أو يعيد كتابة سلسلة التدقيق. السلسلة تكشف
العبث غير المتسق؛ منع الاقتطاع وإرجاع القرص والساعة وحماية المفاتيح يحتاج
مرساة مستقلة أو عتادًا موثوقًا. سياسات الحفظ والإجهاد وقطع الطاقة وiPhone
وRust والتثبيت الحقيقي خارج نطاق هذه النتيجة.

الحدود: حمولة 1 MiB، مسار 32 عقدة، معرفات ASCII محدودة، أعداد من صفر إلى
`2**63-1`. استخدم قرصًا خاصًا ولا تحذف السجل لتجاوز حماية التكرار.

## إعادة الاختبار والرجوع

من جذر المستودع، Python 3.11 أو أحدث:

```sh
python -m pip install -r requirements-scck.txt pytest
python -m pytest -q tests/test_scck.py
python -m pytest -q
python -m compileall -q vxruntime tests
```

الاختبارات تستخدم Ed25519 حقيقيًا ومفاتيح محلية وحمولات خاملة. اختبار إعادة
التشغيل يبدأ عملية جديدة؛ لا يماثل قطع طاقة فعليًا. اختبار السباق يستخدم
خيطين وحاجز بدء، ولا يدعي إطلاقهما في النانوثانية نفسها. حقن الفشل يرفض كتابة
حدث التدقيق عبر trigger للتحقق من rollback كامل.
الدليل وبصمات المصادر في `docs/evidence/scck-local-20261027/validation.json`.

الرجوع: عطّل استدعاء البوابة وارجع عن التزام الإضافة؛ احتفظ بقاعدة البيانات
وسجلها وأعلى إصدار. هذه إضافة اختيارية لا تغيّر المسارات القائمة.
